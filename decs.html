Adj and Nei: two CP models for graphs with a given degree sequence

Both models enumerate, up to isomorphism, the simple undirected graphs whose vertex \(i\) has degree \(\mathit{deg}_i\), for a degree sequence \(\mathit{deg} = (\mathit{deg}_0 \le \dots \le \mathit{deg}_{n-1})\). They differ only in how a graph is encoded: Adj uses the \(n \times n\) adjacency matrix, Nei lists the neighbors of each vertex. Each model comes with the same two symmetry breakings (OptLex and OptRevLex) and an optional connectivity constraint.

1. Encoding

A graph on \(n\) vertices is its adjacency matrix: one 0/1 variable per ordered pair of vertices. Vertices are indexed \(0..n-1\) in the formulas and the code, and numbered \(1..n\) in the examples.

The path 1–5–3–4–2

Degree sequence \((1,1,2,2,2)\): vertices 1 and 2 are the ends.

1 2 3 4 5 1 │ 0 0 0 0 1 2 │ 0 0 0 1 0 3 │ 0 0 0 1 1 4 │ 0 1 1 0 0 5 │ 1 0 1 0 0

Notation

  • \(n\): number of vertices; \(\mathit{deg}_i\): degree of vertex \(i\).
  • \(P = |\{(i,j) : i < j,\ \mathit{deg}_i = \mathit{deg}_j\}|\): equal-degree pairs (\(P = n(n-1)/2\) for a regular sequence).
  • Size: number of constraints posted. Arity: number of decision variables in the scope of one constraint.

4. Symmetry breaking

Relabelling the vertices gives another matrix of the same graph. Codish et al.'s OptLex removes most of these copies by ordering the rows: for every pair \(i < j\), row \(i\) is compared with row \(j\) with columns \(i\) and \(j\) removed. OptRevLex reads the rows from the last column instead of the first.

Only pairs of equal degree. With a fixed degree sequence, swapping two vertices of different degrees is not a symmetry (it breaks \(\mathit{deg}\)), so ordering such rows would lose graphs. Both orders are posted only for pairs with \(\mathit{deg}_i = \mathit{deg}_j\), and only when \(n \ge 3\).

Notation: \(M_i^{\setminus\{i,j\}}\) is row \(i\) without columns \(i\) and \(j\) (without); \(\operatorname{rev}\) reads a vector from the end (reverse).

OptLex — addOptLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad M_i^{\setminus\{i,j\}} \;\le_{lex}\; M_j^{\setminus\{i,j\}}$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(without(A[i], i, j), without(A[j], i, j)));

OptRevLex — addOptRevLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \operatorname{rev}\!\big(M_i^{\setminus\{i,j\}}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_j^{\setminus\{i,j\}}\big)$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(reverse(without(A[i], i, j)), reverse(without(A[j], i, j))));
Partial symmetry breaking. Both orders are sound: no graph is lost. They are not complete: a graph can still be found several times, with different labellings. The results therefore count solutions, not distinct graphs. Example: there are 6 non-isomorphic 3-regular graphs on 8 vertices; OptLex finds 13 solutions and OptRevLex 15.

5. Connectivity — addUpperOffDiagonal (OptRevLex only)

Restricts the search to connected graphs: every vertex except the last has a neighbor with a larger index.

$$\forall i \in [0, n-1): \quad \sum_{v=i+1}^{n-1} M_{iv} > 0$$
Size: \(n-1\)Arity: \(n-1-i\) for vertex \(i\)
for (int i = 0; i < n - 1; i++) {
    IloIntExpr[] upper = new IloIntExpr[n - 1 - i];
    for (int v = i + 1; v < n; v++) upper[v - i - 1] = A[i][v];
    cp.add(cp.gt(cp.sum(upper), 0));
}
Safe for regular sequences only. It is valid with OptRevLex. With a regular sequence any vertex can take any label, so no connected graph is lost. With unequal degrees only equal-degree vertices can swap labels, and some connected graphs have no valid labelling: e.g. \(K_{2,3}\) for \((2,2,2,3,3)\), where vertex 4 has neighbors 1, 2, 3 only. The constraint is posted anyway; for non-regular sequences the counts may be too low (7 of the 144 graphic sequences with \(n \le 6\)).

\(X\): \(M_{ij}\), \(n^2\) variables, \(D = \{0,1\}\)
\(C\): A1 + A2 + A3 + OptLex

public static Result optRevLexAdj(int[] deg, boolean connectivity, String title) throws IloException {
    IloCP cp = new IloCP();
    IloIntVar[][] M = buildAdjacencyModel(cp, deg);
    addOptRevLex(cp, M, deg);
    if (connectivity) addUpperOffDiagonal(cp, M);
    return solve(cp, M, false, title);
}

Every model is solved with the same settings: depth-first search, default inference level Low, all solutions enumerated.

1. Encoding

Row \(i\) lists the neighbors of vertex \(i\) as labels \(1..n\) (vertex \(v\) is written \(v+1\) in the code, so that 0 can mean "empty slot"). Every row has \(D = \max_i \mathit{deg}_i\) slots; the \(D - \mathit{deg}_i\) unused slots hold 0. Where the zeros sit depends on the symmetry breaking, and the neighbors are always strictly ordered:

OrderRow layoutNeighbors \(\{2,5\}\), \(D = 4\)
OptRevLexneighbors strictly increasing, then the zeros2 5 0 0
OptLexthe mirror image: zeros, then neighbors strictly decreasing0 0 5 2

1 │ 0 5 2 │ 0 4 3 │ 5 4 4 │ 3 2 5 │ 3 1

Path 1–3–5–4–2, OptRevLex layout

1 │ 3 0 2 │ 4 0 3 │ 1 5 4 │ 2 5 5 │ 3 4

2. Variables and domains

The zeros and the neighbor labels are fixed in the domains when the variables are created: a zero slot can only be 0, and a neighbor slot can be any label except the vertex's own.

$$X = \{\, M_{ik} : 0 \le i < n,\ 0 \le k < D \,\}, \qquad \{v+1 : \{i,v\} \in E\} = \{M_{ik} : M_{ik} \neq 0\}$$ $$D(M_{ik}) = \{0\}\ \text{(zero slot)}, \qquad D(M_{ik}) = \{1,\dots,n\} \setminus \{i+1\}\ \text{(neighbor slot: no self-loop)}$$
|X| = \(nD\) variables, of which \(\sum_i (D - \mathit{deg}_i)\) are fixed to 0|D| = 1 (zero slot) or \(n-1\) (neighbor slot)
// buildRevLexNeighborsModel: neighbors in slots 0..deg[i]-1, then zeros (2 5 0 0)
for (int k = 0; k < D; k++) M[i][k] = (k < deg[i]) ? neighborVar(cp, n, i) : cp.intVar(0, 0);

// buildLexNeighborsModel: zeros in slots 0..D-deg[i]-1, then neighbors (0 0 5 2)
int first = D - deg[i];
for (int k = 0; k < D; k++) M[i][k] = (k < first) ? cp.intVar(0, 0) : neighborVar(cp, n, i);

private static IloIntVar neighborVar(IloCP cp, int n, int i) throws IloException {
    int[] labels = new int[n - 1];
    for (int v = 1, k = 0; v <= n; v++) if (v != i + 1) labels[k++] = v;
    return cp.intVar(labels);
}

3. Base constraints

Notation: \(\#_a(M_i) = |\{k : M_{ik} = a\}|\), the number of occurrences of \(a\) in row \(i\) (cp.count(M[i], a)).

#ConstraintFormulaSizeArity
N1Strictly ordered neighbors\(M_{ik} < M_{i,k+1}\) (RevLex) or \(>\) (Lex)\(\sum_i \max(\mathit{deg}_i - 1, 0)\)2
N2Undirected\(\#_{v+1}(M_u) = \#_{u+1}(M_v),\ u < v\)\(n(n-1)/2\)\(2D\)

The other properties of a simple graph come from the domains: the zero slots fix the degree (row \(i\) has exactly \(\mathit{deg}_i\) neighbor slots, all \(\ge 1\)), and the missing label \(i+1\) forbids self-loops. N1 then forbids a repeated neighbor and leaves a single row per neighbor set, so no degree count and no all-different constraint are needed.

N1 — Strictly ordered neighbors (in the builders)

$$\text{RevLex (2 5 0 0):}\quad M_{ik} < M_{i,k+1} \quad (0 \le k < \mathit{deg}_i - 1)$$ $$\text{Lex (0 0 5 2):}\quad M_{ik} > M_{i,k+1} \quad (D-\mathit{deg}_i \le k < D-1)$$
Size: \(\max(\mathit{deg}_i - 1, 0)\) per rowArity: 2
// buildRevLexNeighborsModel
for (int k = 0; k + 1 < deg[i]; k++) cp.add(cp.lt(M[i][k], M[i][k + 1]));
// buildLexNeighborsModel
for (int k = first; k + 1 < D; k++) cp.add(cp.gt(M[i][k], M[i][k + 1]));

N2 — Undirected graph — addUndirected

$$\forall\, 0 \le u < v < n: \quad \#_{v+1}(M_u) = \#_{u+1}(M_v)$$
Size: \(n(n-1)/2\)Arity: \(2D\) (rows \(u\) and \(v\))
for (int u = 0; u < n; u++)
    for (int v = u + 1; v < n; v++)
        cp.add(cp.eq(cp.count(M[u], v + 1), cp.count(M[v], u + 1)));

Each count is 0 or 1 because the neighbors are strictly ordered; zero slots never match since labels are \(\ge 1\).

4. Symmetry breaking (on the rows, without 0/1 rows)

The same orders as in Adj, posted directly on the neighbor rows and, as in Adj, only for pairs of equal degree. For a pair \((i,j)\): drop label \(j+1\) from row \(i\) and label \(i+1\) from row \(j\) (if found), then compare the two rows from the last slot.

  • Why it matches Adj. Removing columns \(i, j\) from the 0/1 rows leaves the sets \(S_i = N(i)\setminus\{j\}\) and \(S_j = N(j)\setminus\{i\}\). OptRevLex on the 0/1 rows is decided by the largest vertex \(w\) of \(S_i \,\triangle\, S_j\) (row \(i \le\) row \(j\) iff \(w \in S_j\)); the RevLex rows read from the last slot give the largest neighbor first, so they are decided by \(w\) too. OptLex is decided by the smallest \(w\); the Lex rows read from the last slot give the smallest neighbor first, and the row holding \(w\) is the smaller one, hence the swapped arguments.
  • The zeros never decide. Equal degrees mean the zero slots are in the same places in both rows.

dropLabel — remove a label from a row

$$M_i^{-a}[k] = M_{ik} + t_k\,(M_{i,k-1} - M_{ik}), \qquad t_k = \sum_{m=k}^{D-1} [M_{im} = a] = [k \le p], \qquad M_{i,-1} = 0$$
Size: no constraint; \(D\) expressions per rowEach expression reads: row \(i\)
IloIntExpr atOrBefore = cp.constant(0);   // [k ≤ p]
for (int k = D - 1; k >= 0; k--) {
    atOrBefore = cp.sum(atOrBefore, cp.eq(row[k], label));
    IloIntExpr prev = (k > 0) ? row[k - 1] : cp.constant(0);
    out[k] = cp.sum(row[k], cp.prod(atOrBefore, cp.diff(prev, row[k])));
}

\(p\) is the slot holding the label: the slots before it move one step right and a 0 enters slot 0, the last slot compared. If the label is absent, every \(t_k\) is 0 and the row is unchanged, so no adjacency indicator is needed. Examples: 2 5 0 0 without 5 → 0 2 0 0; 0 0 5 2 without 5 → 0 0 0 2.

OptLex — addOptLexNeiDir

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \operatorname{rev}\!\big(M_j^{-(i+1)}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_i^{-(j+1)}\big)$$
Size: \(P\) lexicographic constraintsArity: \(2D\) (rows \(i\) and \(j\)), through two vectors of \(D\) expressions
if (deg[i] != deg[j]) continue;
IloIntExpr[] ri = dropLabel(cp, M[i], j + 1);   // row i without j+1
IloIntExpr[] rj = dropLabel(cp, M[j], i + 1);   // row j without i+1
cp.add(cp.lexicographic(reverse(rj), reverse(ri)));

OptRevLex — addOptRevLexNeiDir

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \operatorname{rev}\!\big(M_i^{-(j+1)}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_j^{-(i+1)}\big)$$
Size: \(P\) lexicographic constraintsArity: \(2D\), through two vectors of \(D\) expressions

5. Connectivity — addLargestNeighborAbove (OptRevLex only)

The same condition as in Adj: every vertex except the last has a neighbor with a larger label, i.e. its largest neighbor is above it. In the RevLex layout the largest neighbor is the last neighbor slot, so one unary constraint per vertex is enough.

$$\forall i \in [0,n-1): \quad M_{i,\ \max(\mathit{deg}_i - 1,\,0)} > i+1$$
Size: \(n-1\)Arity: 1
for (int i = 0; i < M.length - 1; i++) {
    int last = Math.max(deg[i] - 1, 0);   // deg 0: slot 0 holds 0, so the constraint fails
    cp.add(cp.gt(M[i][last], i + 1));
}
Safe for regular sequences only, for the same reason as in Adj (section 5 of the Adj tab).

3. Correctness

  • Same solutions. For each order, Adj and Nei keep exactly the same labelled graphs (example in section 7 of both tabs). Same solution counts in this benchmark: yes, on every sequence of the benchmark.
  • Checked by brute force on all 144 graphic sequences with \(n \le 6\), against the isomorphism classes: no model loses a graph without connectivity; with connectivity no connected graph is lost for regular sequences, and 7 non-regular sequences lose connected graphs, in both encodings alike.
  • Partial symmetry breaking. OptLex and OptRevLex are sound but not complete: a graph can be found more than once (rarely for \(n \le 6\), often for larger \(n\)). This affects both encodings identically, since they post the same order.

5. Conclusions

  1. Same solutions. For each symmetry breaking, Adj and Nei post the same order and keep exactly the same labelled graphs: identical solution counts on all 14 sequences of the benchmark, with and without connectivity, and on the 144 sequences of the brute-force check.
  2. Smaller model, richer constraints. Nei has far fewer variables (48 instead of 144 for 4-regular graphs on 12 vertices; none of them fixed, since a regular sequence has no zero slot) and moves self-loops and degrees into the domains. In exchange its undirected and symmetry-breaking constraints have larger arity and are built from count and dropLabel expressions, so the number of posted constraints is about the same (168 for Nei, 156 for Adj on that example).
  3. With OptRevLex, Nei is faster. Over the whole benchmark Nei takes 15.6 s instead of 21.3 s on the regular sequences (1.37×) and 5.7 s instead of 7.7 s on the non-regular ones (1.35×). The gap grows with the instance: 1.40× on 4-regular graphs with 12 vertices (12.8 s vs 18.0 s) and 2.4× on 3-regular graphs with 12 vertices. On instances solved in a fraction of a second the two are within noise.
  4. With connectivity, the advantage of Nei is larger. 12.3 s instead of 19.4 s in total (1.58×), 1.68× on 4-regular graphs with 12 vertices: the Nei connectivity constraint is a single bound per vertex (M[i][deg[i]-1] > i+1), the Adj one a sum over a row.
  5. With OptLex, Adj is faster. 32.0 s for Adj against 46.8 s for Nei on the regular sequences (0.68×) and 15.9 s against 20.6 s on the non-regular ones (0.77×); on 4-regular graphs with 12 vertices, 27.5 s against 42.3 s.
  6. Memory. Nei uses more solver memory on the larger instances (10.3 MB against 7.1 MB with OptRevLex on 4-regular graphs with 12 vertices), because of its count and dropLabel expressions; all runs stay below 13 MB.
  7. OptRevLex prunes more than OptLex on regular sequences, in both encodings (e.g. 45,729 instead of 98,223 solutions for 4-regular graphs with 12 vertices), and it is the only order compatible with the connectivity constraint.
Recommendation. The fastest configuration measured is Nei with OptRevLex (optRevLexNeiDir), with or without connectivity. If OptLex is required, use the Adj encoding. These timings come from a single run per configuration on one machine; the differences of a few percent on small instances are not significant.
Benchmark: all solutions enumerated, one run per configuration, on a 4-core Linux machine with IBM CP Optimizer 22.1.1 (depth-first search, inference level Low). Times are wall-clock search times; memory is the solver's PeakMemoryUsage.
