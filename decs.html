Adj and Nei: two CP models for graphs with a given degree sequence

Both models enumerate, up to isomorphism, the simple undirected graphs whose vertex \(i\) has degree \(\mathit{deg}_i\), for a degree sequence \(\mathit{deg} = (\mathit{deg}_0 \le \dots \le \mathit{deg}_{n-1})\). They differ only in how a graph is encoded: Adj uses the \(n \times n\) adjacency matrix, Nei lists the neighbors of each vertex. Adj comes with two symmetry breakings (OptLex and OptRevLex), Nei with OptRevLex only; both have an optional connectivity constraint.

1. Encoding

A graph on \(n\) vertices is its adjacency matrix: one 0/1 variable per ordered pair of vertices. Vertices are indexed \(0..n-1\) in the formulas and the code, and numbered \(1..n\) in the examples.

The paw

Degree sequence \((1,2,2,3)\): the triangle 2–3–4 and the pendant vertex 1.

1 2 3 4 1 │ 0 0 0 1 2 │ 0 0 1 1 3 │ 0 1 0 1 4 │ 1 1 1 0

Notation

  • \(n\): number of vertices; \(\mathit{deg}_i\): degree of vertex \(i\).
  • \(P = |\{(i,j) : i < j,\ \mathit{deg}_i = \mathit{deg}_j\}|\): equal-degree pairs (\(P = n(n-1)/2\) for a regular sequence).
  • Size: number of constraints posted. Arity: number of decision variables in the scope of one constraint.

4. Symmetry breaking

Relabelling the vertices gives another matrix of the same graph. Codish et al.'s OptLex removes most of these copies by ordering the rows: for every pair \(i < j\), row \(i\) is compared with row \(j\) with columns \(i\) and \(j\) removed. OptRevLex reads the rows from the last column instead of the first.

Only pairs of equal degree. With a fixed degree sequence, swapping two vertices of different degrees is not a symmetry (it breaks \(\mathit{deg}\)), so ordering such rows would lose graphs. Both orders are posted only for pairs with \(\mathit{deg}_i = \mathit{deg}_j\), and only when \(n \ge 3\).

Notation: \(M_i^{\setminus\{i,j\}}\) is row \(i\) without columns \(i\) and \(j\) (without); \(\operatorname{rev}\) reads a vector from the end (reverse).

OptLex — addOptLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad M_i^{\setminus\{i,j\}} \;\le_{lex}\; M_j^{\setminus\{i,j\}}$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(without(A[i], i, j), without(A[j], i, j)));

OptRevLex — addOptRevLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \operatorname{rev}\!\big(M_i^{\setminus\{i,j\}}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_j^{\setminus\{i,j\}}\big)$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(reverse(without(A[i], i, j)), reverse(without(A[j], i, j))));
Partial symmetry breaking. Both orders are sound: no graph is lost. They are not complete: a graph can still be found several times, with different labellings. The results therefore count solutions, not distinct graphs. Example: there are 6 non-isomorphic 3-regular graphs on 8 vertices; OptLex finds 13 solutions and OptRevLex 15.

5. Connectivity — addUpperOffDiagonal (OptRevLex only)

Restricts the search to connected graphs: every vertex except the last has a neighbor with a larger index.

$$\forall i \in [0, n-1): \quad \sum_{v=i+1}^{n-1} M_{iv} > 0$$
Size: \(n-1\)Arity: \(n-1-i\) for vertex \(i\)
for (int i = 0; i < n - 1; i++) {
    IloIntExpr[] upper = new IloIntExpr[n - 1 - i];
    for (int v = i + 1; v < n; v++) upper[v - i - 1] = A[i][v];
    cp.add(cp.gt(cp.sum(upper), 0));
}
Safe for regular sequences only. It is valid with OptRevLex. With a regular sequence any vertex can take any label, so no connected graph is lost. With unequal degrees only equal-degree vertices can swap labels, and some connected graphs have no valid labelling: e.g. \(K_{2,3}\) for \((2,2,2,3,3)\), where vertex 4 has neighbors 1, 2, 3 only. The constraint is posted anyway; for non-regular sequences the counts may be too low (7 of the 144 graphic sequences with \(n \le 6\)).

6. Complete models

optLexAdj(deg)
\(X\): \(M_{ij}\), \(n^2\) variables, \(D = \{0,1\}\)
\(C\): A1 + A2 + A3 + OptLex
Size: \(2n + n(n-1)/2 + P\)
optRevLexAdj(deg, connectivity)
\(X\): \(M_{ij}\), \(n^2\) variables, \(D = \{0,1\}\)
\(C\): A1 + A2 + A3 + OptRevLex (+ connectivity)
Size: \(2n + n(n-1)/2 + P\) (+ \(n-1\))
public static Result optRevLexAdj(int[] deg, boolean connectivity, String title) throws IloException {
    IloCP cp = new IloCP();
    IloIntVar[][] M = buildAdjacencyModel(cp, deg);
    addOptRevLex(cp, M, deg);
    if (connectivity) addUpperOffDiagonal(cp, M);
    return solve(cp, M, false, title);
}

Every model is solved with the same settings: depth-first search, default inference level Low, all solutions enumerated.

1. Encoding

Row \(i\) lists the neighbors of vertex \(i\) as labels \(1..n\) (vertex \(v\) is written \(v+1\) in the code, so that 0 can mean "empty slot"). Every row has \(D = \max_i \mathit{deg}_i\) slots: the neighbors strictly increasing, then the \(D - \mathit{deg}_i\) unused slots holding 0. Example: neighbors \(\{2,5\}\) with \(D = 4\) → 2 5 0 0. Nei is used with OptRevLex only.

The paw \((1,2,2,3)\)

1 │ 4 0 0 2 │ 3 4 0 3 │ 2 4 0 4 │ 1 2 3

2. Variables and domains

The zeros and the neighbor labels are fixed in the domains when the variables are created: a zero slot can only be 0, and a neighbor slot can be any label except the vertex's own.

$$X = \{\, M_{ik} : 0 \le i < n,\ 0 \le k < D \,\}, \qquad \{v+1 : \{i,v\} \in E\} = \{M_{ik} : M_{ik} \neq 0\}$$ $$D(M_{ik}) = \{0\}\ \text{(zero slot)}, \qquad D(M_{ik}) = \{1,\dots,n\} \setminus \{i+1\}\ \text{(neighbor slot: no self-loop)}$$
|X| = \(nD\) variables, of which \(\sum_i (D - \mathit{deg}_i)\) are fixed to 0|D| = 1 (zero slot) or \(n-1\) (neighbor slot)
// buildRevLexNeighborsModel: neighbors in slots 0..deg[i]-1, then zeros (2 5 0 0)
for (int k = 0; k < D; k++) M[i][k] = (k < deg[i]) ? neighborVar(cp, n, i) : cp.intVar(0, 0);

private static IloIntVar neighborVar(IloCP cp, int n, int i) throws IloException {
    int[] labels = new int[n - 1];
    for (int v = 1, k = 0; v <= n; v++) if (v != i + 1) labels[k++] = v;
    return cp.intVar(labels);
}

3. Base constraints

Notation: \(\#_a(M_i) = |\{k : M_{ik} = a\}|\), the number of occurrences of \(a\) in row \(i\) (cp.count(M[i], a)).

#ConstraintFormulaSizeArity
N1Strictly ordered neighbors\(M_{ik} < M_{i,k+1}\)\(\sum_i \max(\mathit{deg}_i - 1, 0)\)2
N2Undirected\(\#_{v+1}(M_u) = \#_{u+1}(M_v),\ u < v\)\(n(n-1)/2\)\(2D\)

The other properties of a simple graph come from the domains: the zero slots fix the degree (row \(i\) has exactly \(\mathit{deg}_i\) neighbor slots, all \(\ge 1\)), and the missing label \(i+1\) forbids self-loops. N1 then forbids a repeated neighbor and leaves a single row per neighbor set, so no degree count and no all-different constraint are needed.

N1 — Strictly ordered neighbors (in the builders)

$$M_{ik} < M_{i,k+1} \quad (0 \le k < \mathit{deg}_i - 1)$$
Size: \(\max(\mathit{deg}_i - 1, 0)\) per rowArity: 2
// buildRevLexNeighborsModel
for (int k = 0; k + 1 < deg[i]; k++) cp.add(cp.lt(M[i][k], M[i][k + 1]));

N2 — Undirected graph — addUndirected

$$\forall\, 0 \le u < v < n: \quad \#_{v+1}(M_u) = \#_{u+1}(M_v)$$
Size: \(n(n-1)/2\)Arity: \(2D\) (rows \(u\) and \(v\))
for (int u = 0; u < n; u++)
    for (int v = u + 1; v < n; v++)
        cp.add(cp.eq(cp.count(M[u], v + 1), cp.count(M[v], u + 1)));

Each count is 0 or 1 because the neighbors are strictly ordered; zero slots never match since labels are \(\ge 1\).

4. Symmetry breaking (OptRevLex) — largest neighbor first

For every pair \(i < j\) of equal degree \(d\), only the \(d\) neighbor slots of each row are kept (the zero slots are left out). The labels \(i+1\) and \(j+1\) are removed from both rows, and the neighbors that remain are compared slot by slot from the last neighbor slot down to the first, i.e. largest neighbor first: row \(i\) ≤ row \(j\) (addOptRevLexNeiDir). Row \(i\) never holds its own label \(i+1\), so in practice only \(j+1\) is removed from row \(i\) and \(i+1\) from row \(j\), and only when \(i\) and \(j\) are adjacent; both rows then lose one slot.

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j = d: \quad \begin{cases} \operatorname{rev}\!\big(M_{i,0..d-1}^{-(j+1)}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_{j,0..d-1}^{-(i+1)}\big) & \text{if } i, j \text{ adjacent} \quad (d-1 \text{ slots})\\[2pt] \operatorname{rev}\!\big(M_{i,0..d-1}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_{j,0..d-1}\big) & \text{otherwise} \quad (d \text{ slots}) \end{cases}$$
Size: \(2P\) conditional constraints (ifThen), \(P\) when \(d = 1\)Arity: \(2D\) (rows \(i\) and \(j\))
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++) {
        int d = deg[i];
        if (d != deg[j] || d == 0) continue;
        IloIntExpr[] rowI = neighborSlots(M[i], d), rowJ = neighborSlots(M[j], d);
        IloConstraint adjacent = cp.eq(cp.count(M[i], j + 1), 1);
        cp.add(cp.ifThen(cp.not(adjacent), cp.lexicographic(reverse(rowI), reverse(rowJ))));
        if (d > 1)   // with one neighbor, removing it leaves nothing to compare
            cp.add(cp.ifThen(adjacent, cp.lexicographic(reverse(dropLabel(cp, rowI, j + 1)),
                                                        reverse(dropLabel(cp, rowJ, i + 1)))));
    }

dropLabel — delete the slot holding a label

$$M_i^{-a}[k] = M_{ik} + s_k\,(M_{i,k+1} - M_{ik}), \qquad s_k = \sum_{m=0}^{k} [M_{im} = a] = [k \ge p], \qquad 0 \le k \le D-2$$
Size: no constraint; \(D-1\) expressions per rowEach expression reads: row \(i\)
IloIntExpr[] out = new IloIntExpr[D - 1];
IloIntExpr atOrAfter = cp.constant(0);   // [k ≥ p]
for (int k = 0; k < D - 1; k++) {
    atOrAfter = cp.sum(atOrAfter, cp.eq(row[k], label));
    out[k] = cp.sum(row[k], cp.prod(atOrAfter, cp.diff(row[k + 1], row[k])));
}

\(p\) is the slot holding the label; the slots after it move one step left and the row becomes one slot shorter, with no 0 added. Example: 2 5 7 without 2 → 5 7. Here it is applied to the \(d\) neighbor slots only, and only when the label is in the row, i.e. when \(i\) and \(j\) are adjacent.

  • The zeros never decide. They are left out of the comparison (neighborSlots keeps the first \(d\) slots).
  • It is the OptRevLex order of Adj. With \(S_i = N(i)\setminus\{j\}\) and \(S_j = N(j)\setminus\{i\}\) (same size), reading the increasing lists from the end decides at the largest vertex \(w\) of \(S_i \,\triangle\, S_j\): row \(i\) ≤ row \(j\) iff \(w \in S_j\). OptRevLexAdj reads row \(i\) without columns \(i, j\) from the right and decides at the same \(w\), with the same answer. Both models therefore keep exactly the same labelled graphs, on every degree sequence.
  • Sound. Checked by brute force on all 278 graphic sequences with \(n \le 6\), sorted increasingly and decreasingly: no graph is lost, and the solution counts equal those of optRevLexAdj on every sequence.

5. Connectivity — addLargestNeighborAbove

One unary constraint per vertex, on the slot of its largest neighbor (the last neighbor slot \(\mathit{deg}_i - 1\)), for every row except the last: every vertex has a neighbor above it, the Nei form of the Adj upper off-diagonal (Adj tab, section 5).

$$\forall i \in [0,n-1): \quad M_{i,\ \mathit{deg}_i - 1} > i+1$$
Size: \(n-1\)Arity: 1
for (int i = 0; i < M.length - 1; i++) {
    int last = Math.max(deg[i] - 1, 0);   // deg 0: slot 0 holds 0, so the constraint fails
    cp.add(cp.gt(M[i][last], i + 1));
}
Same behavior as the Adj upper off-diagonal. \(M_{i,\mathit{deg}_i-1} > i+1\) says exactly that vertex \(i\) has a neighbor above it, and the Nei order is the OptRevLex order of Adj (section 4), so both models keep the same connected labelled graphs. 6. Complete models

optRevLexNeiDir(deg, connectivity)
\(X\): \(M_{ik}\), \(nD\) variables (layout 2 5 0 0)
\(C\): N1 (\(<\)) + N2 + row pairs compared largest neighbor first (+ connectivity)
Size: \(\sum_i \max(\mathit{deg}_i-1,0) + n(n-1)/2 + 2P\) (+ \(n-1\))
public static Result optRevLexNeiDir(int[] deg, boolean connectivity, String title) throws IloException {
    IloCP cp = new IloCP();
    IloIntVar[][] M = buildRevLexNeighborsModel(cp, deg);   // domains + N1 + N2
    addOptRevLexNeiDir(cp, M, deg);
    if (connectivity) addLargestNeighborAbove(cp, M, deg);
    return solve(cp, M, true, title);
}

Three models were run on every sequence (branch newpaper, working tree on commit a912ffa with the new addOptRevLexNeiDir, 2026-11-18): optLexAdj, optRevLexAdj and optRevLexNeiDir (Nei, Nei tab section 4); connectivity off, all solutions enumerated, one run per cell. The regular families 1-4 were also run with connectivity on (section 6).

Loaded machine. Other programs (browser, IDE) were running: the load average was about 6 on 4 cores. Adj took about twice as long as in the previous run (OptRevLexAdj: 136.41 s in total against 66.44 s; OptLexAdj on N14_d3: 191.05 s against 74.00 s). Ratios inside this run are more reliable than times compared across runs, but small differences are noise; a rerun on an idle machine is needed before quoting times.

2. The Nei order is the OptRevLex order of Adj

In this run optRevLexNeiDir returns exactly the solution counts of optRevLexAdj on all 27 rows (e.g. 18,345 for N14_d3), and the same connected counts on all 15 regular rows with connectivity on. This follows from the definitions, for every pair \(i < j\) of equal degree, with \(S_i = N(i)\setminus\{j\}\) and \(S_j = N(j)\setminus\{i\}\) (same size):

  • OptRevLexAdj compares rows \(i\) and \(j\) without columns \(i, j\), from the right: the first differing column is the largest vertex \(w\) of \(S_i \,\triangle\, S_j\), and row \(i \le\) row \(j\) iff \(w \in S_j\).
  • Nei compares the increasing lists of \(S_i\) and \(S_j\) from the last slot: they first differ at the same \(w\), and the list holding the larger value there is the one holding \(w\), so row \(i \le\) row \(j\) iff \(w \in S_j\).
Consequence. Nei and OptRevLexAdj keep exactly the same labelled graphs, with and without connectivity, so the encoding comparison is OptRevLexAdj against Nei. OptLexAdj is shown as a reference.

8. Correctness

  • Same solutions as OptRevLexAdj on all 27 rows, and the same connected counts on the 15 regular rows, as section 2 predicts.
  • Sound. Checked by brute force on all 278 graphic sequences with \(n \le 6\) (sorted increasingly and decreasingly) against the isomorphism classes: no graph is lost, and the counts equal those of optRevLexAdj on every sequence. With connectivity, Nei and Adj lose connected graphs on the same 7 non-regular sequences of the 96 that have one, and on no regular sequence.
  • Complement duality (Adj). OptLexAdj on a dense complement gives exactly the OptRevLexAdj count of the sparse sequence, and the reverse (133 / 192 for N10_d6 and N10_d3, 614 / 750 for N10_d5 and N10_d4, 1,462 / 4,984 for N12_d8 and N12_d3).

9. Conclusions

  1. Nei now reproduces OptRevLexAdj, with and without connectivity (section 2): the comparison is between two encodings of the same search space.
  2. Sparse graphs: Nei is faster. Cubic 1.83× (N14_d3: 42.81 s against 84.48 s), 2-regular 2.02×, trees 1.47×, heterogeneous 1.27×; Nei is the fastest of the three models on the five sparsest instances.
  3. Denser graphs: Nei is much slower. Quartic 0.20× (N12_d4: 129.90 s against 28.06 s), dense complements 0.03× (N12_d8: 82.08 s against 2.38 s), bi-degree 0.26×. Overall Nei takes 298.05 s against 136.41 s (0.46×).
  4. Connectivity: same picture, 206.24 s against 84.98 s on families 1-4, with Nei 4.14× faster on N14_d3 and 0.03× on N12_d8.
  5. Compared with an earlier encoding of the same order. In the run of commit 89a32b6, Nei posted the OptRevLex order of Adj in another form and took 41.49 s in total, against 66.44 s for OptRevLexAdj in that run. Here it takes 298.05 s against 136.41 s. Even allowing for the loaded machine, the reversed comparison on dropLabel expressions seems to propagate worse on dense rows; this is worth checking on an idle machine.
  6. Memory. Nei uses the most memory on dense and regular instances (N12_d8: 14.5 MB against 4.4 MB for OptRevLexAdj; N10_d8: 9.8 MB against 2.5 MB) and the least on the tree sequences.
Summary. Nei and OptRevLexAdj now return the same solutions. Nei pays off on sparse sequences and loses heavily as the density grows. These are single runs on a loaded machine: differences under about 15 % are within noise, and the times should be confirmed on an idle machine.
Benchmark: all solutions enumerated, one run per configuration, on a 4-core Linux machine with IBM CP Optimizer 22.1.1 (depth-first search, inference level Low). Times are wall-clock search times; memory is the solver's PeakMemoryUsage.
