Adj and Nei: two CP models for graphs with a given degree sequence

Both models enumerate, up to isomorphism, the simple undirected graphs whose vertex \(i\) has degree \(\mathit{deg}_i\), for a degree sequence \(\mathit{deg} = (\mathit{deg}_0 \le \dots \le \mathit{deg}_{n-1})\). They differ only in how a graph is encoded: Adj uses the \(n \times n\) adjacency matrix, Nei lists the neighbors of each vertex. Adj comes with two symmetry breakings (OptLex and OptRevLex), Nei with OptRevLex only; both have an optional connectivity constraint.

1. Encoding

A graph on \(n\) vertices is its adjacency matrix: one 0/1 variable per ordered pair of vertices. Vertices are indexed \(0..n-1\) in the formulas and the code, and numbered \(1..n\) in the examples.

The paw

Degree sequence \((1,2,2,3)\): the triangle 2–3–4 and the pendant vertex 1.

1 2 3 4 1 │ 0 0 0 1 2 │ 0 0 1 1 3 │ 0 1 0 1 4 │ 1 1 1 0

Notation

  • \(n\): number of vertices; \(\mathit{deg}_i\): degree of vertex \(i\).
  • \(P = |\{(i,j) : i < j,\ \mathit{deg}_i = \mathit{deg}_j\}|\): equal-degree pairs (\(P = n(n-1)/2\) for a regular sequence).
  • Size: number of constraints posted. Arity: number of decision variables in the scope of one constraint.

4. Symmetry breaking

Relabelling the vertices gives another matrix of the same graph. Codish et al.'s OptLex removes most of these copies by ordering the rows: for every pair \(i < j\), row \(i\) is compared with row \(j\) with columns \(i\) and \(j\) removed. OptRevLex reads the rows from the last column instead of the first.

Only pairs of equal degree. With a fixed degree sequence, swapping two vertices of different degrees is not a symmetry (it breaks \(\mathit{deg}\)), so ordering such rows would lose graphs. Both orders are posted only for pairs with \(\mathit{deg}_i = \mathit{deg}_j\), and only when \(n \ge 3\).

Notation: \(M_i^{\setminus\{i,j\}}\) is row \(i\) without columns \(i\) and \(j\) (without); \(\operatorname{rev}\) reads a vector from the end (reverse).

OptLex — addOptLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad M_i^{\setminus\{i,j\}} \;\le_{lex}\; M_j^{\setminus\{i,j\}}$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(without(A[i], i, j), without(A[j], i, j)));

OptRevLex — addOptRevLex

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \operatorname{rev}\!\big(M_i^{\setminus\{i,j\}}\big) \;\le_{lex}\; \operatorname{rev}\!\big(M_j^{\setminus\{i,j\}}\big)$$
Size: \(P\) lexicographic constraintsArity: \(2(n-2)\)
if (deg[i] != deg[j]) continue;
cp.add(cp.lexicographic(reverse(without(A[i], i, j)), reverse(without(A[j], i, j))));
Partial symmetry breaking. Both orders are sound: no graph is lost. They are not complete: a graph can still be found several times, with different labellings. The results therefore count solutions, not distinct graphs. Example: there are 6 non-isomorphic 3-regular graphs on 8 vertices; OptLex finds 13 solutions and OptRevLex 15.

5. Connectivity — addUpperOffDiagonal (OptRevLex only)

Restricts the search to connected graphs: every vertex except the last has a neighbor with a larger index.

$$\forall i \in [0, n-1): \quad \sum_{v=i+1}^{n-1} M_{iv} > 0$$
Size: \(n-1\)Arity: \(n-1-i\) for vertex \(i\)
for (int i = 0; i < n - 1; i++) {
    IloIntExpr[] upper = new IloIntExpr[n - 1 - i];
    for (int v = i + 1; v < n; v++) upper[v - i - 1] = A[i][v];
    cp.add(cp.gt(cp.sum(upper), 0));
}
Safe for regular sequences only. It is valid with OptRevLex. With a regular sequence any vertex can take any label, so no connected graph is lost. With unequal degrees only equal-degree vertices can swap labels, and some connected graphs have no valid labelling: e.g. \(K_{2,3}\) for \((2,2,2,3,3)\), where vertex 4 has neighbors 1, 2, 3 only. The constraint is posted anyway; for non-regular sequences the counts may be too low (7 of the 144 graphic sequences with \(n \le 6\)).

6. Complete models

optLexAdj(deg)
\(X\): \(M_{ij}\), \(n^2\) variables, \(D = \{0,1\}\)
\(C\): A1 + A2 + A3 + OptLex
Size: \(2n + n(n-1)/2 + P\)
optRevLexAdj(deg, connectivity)
\(X\): \(M_{ij}\), \(n^2\) variables, \(D = \{0,1\}\)
\(C\): A1 + A2 + A3 + OptRevLex (+ connectivity)
Size: \(2n + n(n-1)/2 + P\) (+ \(n-1\))
public static Result optRevLexAdj(int[] deg, boolean connectivity, String title) throws IloException {
    IloCP cp = new IloCP();
    IloIntVar[][] M = buildAdjacencyModel(cp, deg);
    addOptRevLex(cp, M, deg);
    if (connectivity) addUpperOffDiagonal(cp, M);
    return solve(cp, M, false, title);
}

Every model is solved with the same settings: depth-first search, default inference level Low, all solutions enumerated.

7. Example: \(\mathit{deg} = (1,2,2,3)\), the paw

Only one labelled graph has this degree sequence, so every model returns the same matrix:

  • vertex 4 has degree 3, so it is adjacent to 1, 2 and 3;
  • vertex 1 has degree 1 and is already full;

Here \(n = 4\) and the only equal-degree pair is \((2,3)\), so \(P = 1\). The model has 16 variables and posts A1 (4), A2 (4), A3 (6), one lexicographic constraint, and with connectivity 3 more constraints.

1. Encoding

Row \(i\) lists the neighbors of vertex \(i\) as labels \(1..n\) (vertex \(v\) is written \(v+1\) in the code, so that 0 can mean "empty slot"). Every row has \(D = \max_i \mathit{deg}_i\) slots: the neighbors strictly increasing, then the \(D - \mathit{deg}_i\) unused slots holding 0. Example: neighbors \(\{2,5\}\) with \(D = 4\) → 2 5 0 0. Nei is used with OptRevLex only.

The paw \((1,2,2,3)\)

1 │ 4 0 0 2 │ 3 4 0 3 │ 2 4 0 4 │ 1 2 3

2. Variables and domains

The zeros and the neighbor labels are fixed in the domains when the variables are created: a zero slot can only be 0, and a neighbor slot can be any label except the vertex's own.

$$X = \{\, M_{ik} : 0 \le i < n,\ 0 \le k < D \,\}, \qquad \{v+1 : \{i,v\} \in E\} = \{M_{ik} : M_{ik} \neq 0\}$$ $$D(M_{ik}) = \{0\}\ \text{(zero slot)}, \qquad D(M_{ik}) = \{1,\dots,n\} \setminus \{i+1\}\ \text{(neighbor slot: no self-loop)}$$
|X| = \(nD\) variables, of which \(\sum_i (D - \mathit{deg}_i)\) are fixed to 0|D| = 1 (zero slot) or \(n-1\) (neighbor slot)
// buildRevLexNeighborsModel: neighbors in slots 0..deg[i]-1, then zeros (2 5 0 0)
for (int k = 0; k < D; k++) M[i][k] = (k < deg[i]) ? neighborVar(cp, n, i) : cp.intVar(0, 0);

private static IloIntVar neighborVar(IloCP cp, int n, int i) throws IloException {
    int[] labels = new int[n - 1];
    for (int v = 1, k = 0; v <= n; v++) if (v != i + 1) labels[k++] = v;
    return cp.intVar(labels);
}

3. Base constraints

Notation: \(\#_a(M_i) = |\{k : M_{ik} = a\}|\), the number of occurrences of \(a\) in row \(i\) (cp.count(M[i], a)).

#ConstraintFormulaSizeArity
N1Strictly ordered neighbors\(M_{ik} < M_{i,k+1}\)\(\sum_i \max(\mathit{deg}_i - 1, 0)\)2
N2Undirected\(\#_{v+1}(M_u) = \#_{u+1}(M_v),\ u < v\)\(n(n-1)/2\)\(2D\)

The other properties of a simple graph come from the domains: the zero slots fix the degree (row \(i\) has exactly \(\mathit{deg}_i\) neighbor slots, all \(\ge 1\)), and the missing label \(i+1\) forbids self-loops. N1 then forbids a repeated neighbor and leaves a single row per neighbor set, so no degree count and no all-different constraint are needed.

N1 — Strictly ordered neighbors (in the builders)

$$M_{ik} < M_{i,k+1} \quad (0 \le k < \mathit{deg}_i - 1)$$
Size: \(\max(\mathit{deg}_i - 1, 0)\) per rowArity: 2
// buildRevLexNeighborsModel
for (int k = 0; k + 1 < deg[i]; k++) cp.add(cp.lt(M[i][k], M[i][k + 1]));

N2 — Undirected graph — addUndirected

$$\forall\, 0 \le u < v < n: \quad \#_{v+1}(M_u) = \#_{u+1}(M_v)$$
Size: \(n(n-1)/2\)Arity: \(2D\) (rows \(u\) and \(v\))
for (int u = 0; u < n; u++)
    for (int v = u + 1; v < n; v++)
        cp.add(cp.eq(cp.count(M[u], v + 1), cp.count(M[v], u + 1)));

Each count is 0 or 1 because the neighbors are strictly ordered; zero slots never match since labels are \(\ge 1\).

4. Symmetry breaking (OptRevLex) — rows of equal degree decrease

Nei uses its own order, independent of Adj, on the rows exactly as they are stored (2 5 0 0): for every pair \(i < j\) of equal degree, row \(i\) ≥ row \(j\), compared slot by slot from the first slot. If \(i\) and \(j\) are adjacent, the slot holding \(j+1\) is first deleted from row \(i\) and the slot holding \(i+1\) from row \(j\), and the two rows are compared one slot shorter (addOptRevLexNeiDir).

$$\forall\, i < j,\ \mathit{deg}_i = \mathit{deg}_j: \quad \begin{cases} M_j^{-(i+1)} \;\le_{lex}\; M_i^{-(j+1)} & \text{if } i, j \text{ adjacent} \quad (D-1 \text{ slots})\\[2pt] M_j \;\le_{lex}\; M_i & \text{otherwise} \quad (D \text{ slots}) \end{cases}$$
Size: \(2P\) conditional constraints (ifThen)Arity: \(2D\) (rows \(i\) and \(j\))
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++) {
        if (deg[i] != deg[j] || deg[i] == 0) continue;
        IloConstraint adjacent = cp.eq(cp.count(M[i], j + 1), 1);
        cp.add(cp.ifThen(cp.not(adjacent), cp.lexicographic(M[j], M[i])));
        if (M[i].length > 1)   // with one slot, deleting leaves nothing to compare
            cp.add(cp.ifThen(adjacent, cp.lexicographic(dropLabel(cp, M[j], i + 1),
                                                        dropLabel(cp, M[i], j + 1))));
    }

dropLabel — delete the slot holding a label

$$M_i^{-a}[k] = M_{ik} + s_k\,(M_{i,k+1} - M_{ik}), \qquad s_k = \sum_{m=0}^{k} [M_{im} = a] = [k \ge p], \qquad 0 \le k \le D-2$$
Size: no constraint; \(D-1\) expressions per rowEach expression reads: row \(i\)
IloIntExpr[] out = new IloIntExpr[D - 1];
IloIntExpr atOrAfter = cp.constant(0);   // [k ≥ p]
for (int k = 0; k < D - 1; k++) {
    atOrAfter = cp.sum(atOrAfter, cp.eq(row[k], label));
    out[k] = cp.sum(row[k], cp.prod(atOrAfter, cp.diff(row[k + 1], row[k])));
}

\(p\) is the slot holding the label; the slots after it move one step left and the row becomes one slot shorter, with no 0 added. Examples: 2 5 0 0 without 2 → 5 0 0. It is only used when the label is in the row, i.e. when \(i\) and \(j\) are adjacent.

  • The zeros never decide. Equal degrees mean the zero slots are in the same places in both rows.
  • Sound. Checked by brute force on all 144 graphic sequences with \(n \le 6\): no graph is lost.
  • Not the Adj order. Nei may keep other labellings than Adj. For the path \((1,1,2,2,2)\), OptRevLexNeiDir keeps the labelling 1–5–3–4–2 (rows 5 0 / 4 0 / 4 5 / 2 3 / 1 3), OptRevLexAdj keeps 1–3–5–4–2.

5. Connectivity — addLargestNeighborAbove (under revision)

One unary constraint per vertex, on the slot of its largest neighbor (the last neighbor slot \(\mathit{deg}_i - 1\)), for every row except the last.

$$\forall i \in [0,n-1): \quad M_{i,\ \mathit{deg}_i - 1} > i+1$$
Size: \(n-1\)Arity: 1
for (int i = 0; i < M.length - 1; i++) {
    int last = Math.max(deg[i] - 1, 0);   // deg 0: slot 0 holds 0, so the constraint fails
    cp.add(cp.gt(M[i][last], i + 1));
}
Not compatible with the current row order. Decreasing rows give the large labels to the first vertices, and the last vertices are then left with smaller neighbors only. Combined with the order of section 4, this constraint loses connected graphs even for regular sequences: the cycles \(C_4, C_5, C_6\) and the 3- and 4-regular graphs on 6 vertices (brute force, \(n \le 6\)). A compatible version is being validated.

optRevLexNeiDir(deg, connectivity)
\(X\): \(M_{ik}\), \(nD\) variables (layout 2 5 0 0)

public static Result optRevLexNeiDir(int[] deg, boolean connectivity, String title) throws IloException {
    IloCP cp = new IloCP();
    IloIntVar[][] M = buildRevLexNeighborsModel(cp, deg);   // domains + N1 + N2

}

6. Correctness

  • Same solutions in this run. Adj and Nei returned the same number of solutions on all 26 rows: in commit 89a32b6 Nei posted the Adj order on its rows. With the current Nei order (Nei tab, section 4) the counts may differ from Adj.
  • Complement duality (Adj). OptLexAdj on a dense complement gives exactly the OptRevLexAdj count of the sparse sequence, and the reverse: 133 and 192 for N10_d6 vs 192 and 133 for N10_d3, 614 and 750 for N10_d5 vs N10_d4, 1,462 and 4,984 for N12_d8 vs N12_d3. Complementing a graph swaps 0 and 1 off the diagonal, which turns one order into the other.
  • Checked by brute force on all 144 graphic sequences with \(n \le 6\) against the isomorphism classes: no graph is lost. The symmetry breakings are partial, so a graph can be counted several times (e.g. 18,345 OptRevLex solutions for N14_d3).

7. Conclusions

  1. No single winner. Over the whole set Nei is faster (1.68×: 41.49 s against 69.80 s), but this comes from the largest instances; without N14_d3 and N12_d4 the two encodings are tied (0.94×). Which one is better depends on the family.
  2. Sparse regular graphs: Nei, and the gap grows with \(n\). Cubic graphs: 3.99× over the family; on N14_d3, 7.70 s against 32.16 s (4.2×). 2-regular graphs: 1.92×. Here Nei has \(3n\) or \(2n\) variables against \(n^2\).
  3. Hubs and leaves: Nei. 1.53× over the heterogeneous family (3.25 s against 5.43 s on N14_11111122233457). Tree degree sequences are a tie (1.08×).
  4. Dense graphs: Adj. In this set Adj wins on every instance of density 0.4 or more (N11_d4, N10_d4, N10_d5, N12_d8, section 5); 2.5× over the complements (0.40×): N12_d8 takes 2.76 s with Adj and 6.99 s with Nei. Nei then has almost as many variables as Adj, with large domains and long rows.
  5. Bi-degree graphs: Adj (0.36×), although they are sparse.
  6. Quartic graphs: Nei over the family (1.29×; N12_d4 13.67 s against 18.72 s), but Adj wins on the smaller N10_d4 (0.14 s against 0.21 s) and N11_d4 (1.28 s against 1.67 s).
  7. Memory. Nei uses more memory on regular and dense sequences (13.1 MB against 4.3 MB on N12_d8; 8.6 MB against 2.5 MB for the single graph N10_d8), and about the same on the sparse non-regular ones (5.0 MB against 5.2 MB on N14_11111112223334). Every OptRevLex run stays below 14 MB.
  8. Unigraphic sequences take about 0.01 s in both encodings: the fixed overhead is negligible.
  9. Order for Adj. OptRevLexAdj keeps far fewer solutions than OptLexAdj on sparse graphs (18,345 against 172,753 for N14_d3) and is faster; on the dense complements OptLexAdj keeps fewer (1,462 against 4,984 for N12_d8), as the complement duality predicts.
